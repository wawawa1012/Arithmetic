### 💡 核心数据结构与算法总结

#### 一、栈 (Stack) 的三大适用场景 (后进先出 LIFO)
1. **“洋葱模型” / 嵌套匹配：** 信息一层包着一层（如 `3[a2[c]]`、括号匹配、JSON 语法解析）。外层状态必须先**“存档 (Push)”**挂起，等待最内层逻辑处理完毕后，再**“读档 (Pop)”**向外合并。
2. **“历史清算” / 寻找下一个更大值：** 站在当前节点无法立刻得到答案，过去的元素处于“待满足”的等待状态（如“每日温度”）。单调栈允许未来某个符合条件的强力元素降临时，将历史记录像割麦子一样**批量清算出栈**。
3. **“时光倒流” / 撤销动作 (Undo)：** 只能操作“距离当前最近的一个历史动作”（如文本编辑器退格、逆波兰表达式中的连续两数计算）。

#### 二、回溯算法 (Backtracking) 的三大适用场景 (多重宇宙的探索)
在面对算法题时，一旦看到以下三个特征，**必须放弃 `for` 循环的线性思维，直接套用回溯算法的“克隆人探险”模板：**
1. **关键词：“找出所有可能的解 / 方案” (穷举组合/排列/子集)：** * **雷达：** 只要题目要求你返回 `vector<vector<int>>` 这种“包含所有结局的二维大铁桶”，且数据规模通常较小（$N \le 20$），绝对是回溯。
* **动作：** 使用 `push_back` 拿取，派发克隆人探索，探索结束后严格执行 `pop_back` 恢复背包原状（时光倒流）。
2. **关键词：“满足某条件的 / 有效的” (限制条件下的路径探索)：**
* **雷达：** 比如生成“有效的”括号、走迷宫、“不互相攻击”的八皇后。有规则约束着你不能瞎走。
* **动作：** 在向下分裂平行宇宙前，先用 `if` 拦截非法分支（剪枝）。走到绝路立刻 `return` 撤销。
3. **关键词：“凑成总和 / 无限次使用” (无限火力的资源分配)：**
* **雷达：** 给定一个目标值（Target），让你在数组里挑东西凑够它。
* **动作：** 使用 `for (int i = start_index; ...)` 铺设传送门阵列。为了防止出现顺序不同的重复解（如 `[2,3]` 和 `[3,2]`），向下一层派发克隆人时，必须传入当前的 `i`，锁死克隆人只能向右探索，绝不回头。

#### 三、分治法与减治法 (Divide & Decrease and Conquer) (降维打击的艺术)
1. **分治法 (Divide and Conquer) - 老板三板斧：** * 面对庞大的 $O(N^2)$ 计算量，老板**切分 (Divide)** 任务，派克隆人下属去左右半区**干活 (Conquer)**。下属返回排好序/算好的结果后，老板亲自出马利用 $O(N)$ 的 `for` 循环或双指针将两份报告**无缝缝合 (Combine)**。与回溯法不同，分治法是流水线作业，**绝对没有状态撤销**。整体复杂度由主定理瞬间降维至 $O(N \log N)$。
2. **减治法 (Decrease and Conquer) - 物理消灭法则：**
  * 二分查找的本质。老板空降到 `mid` 勘探，通过极其嚣张的物理逻辑判断目标在哪边。**不需要合并！** 每次直接烧毁、丢弃另一半的搜索空间（`left = mid + 1` 或 `right = mid - 1`）。将时间复杂度极致压缩至 $O(\log N)$。

## 1. 八皇后问题 (N-Queens)

**📝 题干描述：**
在一个 8x8 的国际象棋棋盘上放置 8 个皇后，要求它们互不攻击。即任意两个皇后不能处于同一行、同一列或同一斜线上。求出所有的合法摆放方案。

**💡 核心思路 (DFS + 回溯)：**
* **按行推进：** 每一行必定只有一个皇后，因此可以通过递归函数 `trace_back(int r)` 逐行向下放置，避免了复杂的同行冲突检查。
* **空间判定 (AABB思想延伸)：** 使用 `vector<point> queens` 动态记录已放置皇后的坐标。判断对角线冲突时，无需建立复杂的二维映射，直接利用数学绝对值关系：`abs(当前列 - 已存列) == abs(当前行 - 已存行)` 即可精准拦截。
* **状态回溯：** 无论下一行是否找到解，当前行的 `for` 循环在尝试下一个列位置前，必须执行 `queens.pop_back()` 弹出上一次的尝试，恢复棋盘状态（读档）。

## 2. 迷宫寻路 (Maze Pathfinding)

**📝 题干描述：**
给定一个 5x5 的二维数组表示迷宫（`0` 代表空地，`1` 代表墙壁）。要求玩家从起点 `(0, 0)` 出发，只能上、下、左、右移动，寻找一条到达终点 `(4, 4)` 的通关路径，并输出该路径的坐标序列。

**💡 核心思路 (DFS + 状态标记)：**
* **边界与障碍拦截：** 递归函数的起手式先处理异常，遇到数组越界、或者踩到墙壁 `1` 直接 `return false`。
* **防止死循环 (撒面包屑)：** 在 2D 地图上寻路，极易发生“左右横跳”的无限递归。因此在踩上安全格子后，立刻将其值修改为 `2`（标记为已访问），断绝后代递归重走回头路的可能。
* **多米诺骨牌式返回：** 使用 `if (dfs(下一步)) return true;` 进行四周探测。只要最深处摸到了终点 `(4, 4)`，这个 `true` 就会沿着调用栈一路向上传递，瞬间终止其他无意义的方向探索。
* **清理现场：** 如果四个方向全是死胡同，在 `return false` 撤退前，必须把当前格子的 `2` 恢复为 `0`，并从路径 `vector` 中弹出坐标。

## 3. 单词搜索 (Word Search)

**📝 题干描述：**
给定一个 m x n 的二维字符网格 `board` 和一个字符串单词 `target`。如果 `target` 存在于网格中，返回 `true`。单词必须按照字母顺序，通过相邻的单元格内的字母构成，其中“相邻”单元格是那些水平相邻或垂直相邻的单元格。同一个单元格内的字母在一个单词中不允许被重复使用。

**💡 核心思路 (全局搜索 + 索引追踪)：**
* **双层遍历寻找起点：** 目标单词的第一个字母可能在网格的任意位置，因此必须在外部使用双层 `for` 循环遍历整个 `board`，一旦内部的 `dfs` 命中目标，立刻跳出。
* **严格的执行顺序拦截：** 1. 检查坐标越界。2. 检查当前字母是否匹配 `target.at(index)`。3. 检查是否为最后一个字母 `index == target.size() - 1`。
* **完美现场保护：** 由于题目限制“同一个字母不能重复使用”，在进入下一层递归前，使用 `char temp = board[r][c]` 记住当前字母，并将棋盘上的该位置设为 `' '`（空格）作为访问标记。探索失败回溯时，再执行 `board[r][c] = temp` 将字母精准归还。

## 4. 岛屿数量 (Number of Islands)

**📝 题干描述：**
给定一个由 `'1'`（陆地）和 `'0'`（水）组成的的二维网格，计算岛屿的数量。岛屿总是被水包围，并且每座岛屿只能由水平方向或竖直方向上相邻的陆地连接形成。 (LeetCode 200)

**💡 核心思路 (DFS 推土机模式 + 性能优化)：**
* **破坏性探索 (无回溯)：** 与寻找特定路径不同，统计岛屿数量只需要将连通的陆地“消灭”即可。当发现 `'1'` 时，计数器加一，并启动 DFS 将相邻的所有 `'1'` 永久修改为 `'0'`（沉岛），因此无需在递归后执行 `恢复状态` 的回溯操作。
* **守门员拦截前置：** 在 DFS 函数的第一行进行严苛的越界与水面拦截 (`r < 0 || r >= rows` 等)，使得在 `for` 循环扩展方向时可以大胆传入新坐标，无需在循环内部做冗余判断。
* **工程级 C++ 提速：** 使用 `static const int dirs[4][2]` 存储四个扩展方向，避免递归过程中高频重复在栈上分配和销毁数组，显著降低内存与时间开销。

## 5. 全排列 (Permutations)

**📝 题干描述：**
给定一个不含重复数字的数组 `nums`，返回其所有可能的全排列。 (LeetCode 46)

**💡 核心思路 (纯粹状态回溯)：**
* **从具象空间到抽象组合：** 剥离了二维网格的上下左右，`for` 循环遍历整个 `nums` 数组本身就是克隆人在尝试各种“方向”。递归函数的层数，巧妙替代了原本无法预知深度的动态嵌套 `for` 循环。
* **备忘录机制 (Memoization)：** 引入 `vector<bool> used` 数组记录当前路径中已经选取过的数字，充当“撞墙”的拦截条件。
* **完美恢复现场 (Pop Back)：** 当克隆人完成某一条完整路径并返回后，必须通过 `path.pop_back()` 和 `used[i] = false` 将刚放进去的数字“拿回手里”，只有这样才能让 `for` 循环继续推进并尝试其他未选的组合分支。

## 6. 图像渲染 (Flood Fill)

**📝 题干描述：**
给定一个二维整数网格 `image` 代表一幅图像，以及一个起点 `(sr, sc)` 和一个新颜色 `color`。要求将起点及其上下左右所有相连的、且原始颜色与起点相同的像素，全部替换为新颜色。(LeetCode 733)

**💡 核心思路 (滑动窗口的降维打击)：**
* **使用场景与核心优势：** 当题目要求在数组/字符串中寻找满足特定条件的**连续子区间**（如“最长”、“最短”、“总和等于”），且暴力解法需要 $O(N^2)$ 的双层循环时，直接套用滑动窗口。通过左右两个同向移动的指针（绝不走回头路），将时间复杂度极致压缩为 $O(N)$。
* **状态累加与被动收缩：** 维护一个变量 `sum` 记录当前窗口状态。右指针主动探测边界并累加 `sum += nums[right]`。当 `sum >= target` 时，说明当前窗口已达标。为了探寻“最短”极限，必须强迫左指针向右逼近（`sum -= nums[left]; left++;`）吐出冗余元素，直到窗口再次违规，右指针才继续前行。

## 15. 反转链表 (Reverse Linked List)

**📝 题干描述：**
给你单链表的头节点 `head` ，请你反转链表，并返回反转后的链表。(LeetCode 206)

**💡 核心思路 (双指针 / 链表物理防断裂)：**
* **链表的物理特性：** 链表节点在内存中是不连续分布的，完全依靠 `next` 指针维持联系。在修改指针朝向（反转）时，一旦提前断开连接，后续链表将瞬间造成内存丢失（内存泄露）。
* **三步走安全反转法：** 需要维护两个指针：`prev`（初始为 `nullptr`）和 `curr`（初始为 `head`）。
  1. **探路备份：** 在 `curr` 断开与下一节点的连接前，必须先使用临时指针截获其后继节点 `ListNode* temp = curr->next;`。
  2. **原地转身：** 安全备份后，断开当前节点并反转朝向：`curr->next = prev;`。
  3. **双指针推进：** `prev` 移动到当前位置 (`prev = curr;`)，`curr` 移动到刚才备份的位置 (`curr = temp;`)。
* **C++ 内存防坑 (野指针与段错误)：** 声明指针后必须立即初始化。绝对禁止在未分配实际对象内存空间的情况下，声明 `ListNode* temp;` 并直接对其成员进行赋值，这会触发严重的 `Segmentation Fault` (段错误)。直接使用 `temp = curr->next` 即可完成保存。

* **致命陷阱 (短路求值与段错误)：** 在 `while` 循环条件中，必须严格防范对空指针解引用。由于 `fast` 每次需要跳跃两步 (`fast->next->next`)，循环条件必须严格按顺序写为 `fast != nullptr && fast->next != nullptr`。利用 C++ 的短路求值特性，当 `fast` 为空时直接阻断后续判定，防止 `Segmentation Fault` 惨案。

## 25. 最大子数组和 (Maximum Subarray)

**📝 题干描述：**
给你一个整数数组 `nums` ，请你找出一个具有最大和的连续子数组（子数组最少包含一个元素），返回其最大和。 (LeetCode 53)

**💡 核心思路 1 (分治法三板斧 / $O(N \log N)$ 降维)：**
* **老板与克隆人架构：** 把数组劈成两半，派两个经理分别去算出左半场的最大和、右半场的最大和（递归 Conquer）。
* **跨界致命痛点 (Cross_Max)：** 全场最大的子数组可能刚好跨越中线。老板必须亲自出马，在 Combine 合并阶段，以中线为基准，向左连续摸索出最大和，向右连续摸索出最大和，两者相加得到跨界最大值。
* **决断与主定理：** 返回 `max(左半场最大, 右半场最大, 跨界最大)`。该算法完美契合主定理 $T(N) = 2T(N/2) + O(N)$，落入第二分支。


**💡 核心思路 2 (动态规划 Kadane 算法 / $O(N)$ 绝杀)：**
* **物理直觉 (切割历史包袱)：** `dp[i]` 表示“以第 `i` 个数字结尾的最大子数组和”。
* 老板每天只做一个极其冷酷的决定：昨天的队伍 (`dp[i-1]`) 是正资产还是负资产？
  * 如果是正资产（$>0$），我就加入他们：`dp[i] = dp[i-1] + nums[i]`
  * 如果是负资产（$\le 0$），老子今天自己单干：`dp[i] = nums[i]`
* **状态转移方程：** `dp[i] = max(dp[i-1] + nums[i], nums[i])`
* **极限压缩：** 因为今天只看昨天，连 `dp` 数组都可以省略，用一个 `pre` 变量即可，空间复杂度降至 $O(1)$！

**💡 核心思路 (剪胶布的物理艺术)：**
* **找老大与算人数：** 前序遍历的第一项永远是当前辖区的 Root（老大）。拿着 Root 去中序遍历里定位，Root 左边的就是左派系人数（`left_size`），右边的就是右派系。
* **分治 (Divide & Conquer)：** 根据查出来的 `left_size`，像剪胶布一样，把前序和中序数组精准剪成两半，分别下发给构造左子树和右子树的递归函数。
* **⚠️ 工程避坑指南：**
  1. **拒绝 O(N^2)：** 绝对不要在递归里用 `for` 循环去找 Root 的中序位置。必须在起手时建立一个 `unordered_map<int, int>` 账本，实现 O(1) 的瞬间定位。
  2. **坐标系偏移：** 前序数组切分左子树胶布时，起点是 `preorder_left + 1`，长度是 `left_size`，所以终点严格落在 `preorder_left + left_size`。画图推演边界是树形分治的唯一解药。

## 33. Karatsuba 大数乘法 (Karatsuba Multiplication)

**📝 题干描述：**
实现 Karatsuba 算法，将两个大整数的相乘的时间复杂度从 O(N^2) 降维到 O(N^1.585)。

**💡 核心思路 (买二送一的代数黑魔法)：**
* 将长数字对半劈开为高位和低位：`num1 = high1 * 10^m + low1`。
* 传统的暴力分配律需要计算 4 次乘法。Karatsuba 极其精妙地只计算 3 次递归乘法：
  1. 高位乘积：`z2 = high1 * high2`
  2. 低位乘积：`z0 = low1 * low2`
  3. 混合乘积：`z1 = (high1 + low1) * (high2 + low2)`
* 最终通过 `z1 - z2 - z0` 巧妙赎回了中间的交叉项，完成 O(N^2) 铁板的物理击穿。最终组合：`z2 * 10^(2m) + (z1 - z2 - z0) * 10^m + z0`。
* **⚠️ C++ 强类型排雷：**
  1. **溢出杀手：** 过程中的临时变量、劈开的高低位，必须全面使用 `long long` 接管。若用 `int` 中转，十几位的数字会瞬间被截断爆表。
  2. **精度背刺：** `<cmath>` 中的 `pow()` 函数返回的是浮点数 `double`，用于大整数乘法时极易产生末尾精度丢失，导致强转 `long long` 时少一位。必须极其严谨地显式强转 `(long long)pow(10, m)`。

## 39. 二叉树的最近公共祖先 (Lowest Common Ancestor of a Binary Tree)

**📝 题干描述：**

## 🧠 核心心法：动态规划 (DP) 终极辨析与应用场景



在面对迷宫寻路、资源收集、求极值等问题时，这三大算法的物理本质和适用场景有着极其森严的壁垒：

**1. DP (动态规划) vs 贪心 (Greedy)：**
* **贪心法：** 鼠目寸光。只看当前这一步的局部最优收益，绝不考虑未来。极容易死在“前面给甜头，后面有大坑”的陷阱里。
* **动态规划：** 上帝视角的全局最优。它不急于做决定，而是穷尽所有历史可能性后，在当前节点进行“时间线养蛊”，只保留收益最高的那条历史线记入 `dp` 账本。**贪心是不看未来，DP 是通过推演历史决定当下。**

**2. 2D 网格寻路：BFS vs DFS vs DP 怎么选？**
* **BFS (广度优先)：** 像水波纹一样蔓延。**适用场景：** 无权图（走每一步代价都一样是 1），且可以四面八方乱跑。最先碰到的必然是最短距离。
* **DFS (深度优先)：** 不撞南墙不回头。**适用场景：** 需要打印出“所有具体路线”的回溯问题。如果在求极值问题中用纯 DFS，极易陷入 $O(2^N)$ 的指数级爆炸，必须配合 `memo` 记忆化账本来降维。
* **DP (自底向上填表)：** 大老板查历史账本。**适用场景：** 有权图（每步掉血/金币不同），且**不能走回头路**（严格规定只能向右或向下，有向无环图 DAG）。步数不等于代价时，纯 BFS 瘫痪，必须用 DP 记录累计的最优状态。

## 41. 不同路径 (Unique Paths)

**📝 题干描述：**
机器人在 `m x n` 网格的左上角，只能向下或向右移动，求到达右下角共有多少条不同的路径。(LeetCode 62)

**💡 核心思路 (二维 DP 组合推演)：**
* **重叠子问题降维：** 纯 DFS 每次都会重复计算同一个坐标到终点的路径，导致超时。将 DFS 逆向翻转为 DP 填表，时间复杂度瞬间从 $O(2^{m+n})$ 降为 $O(m \times n)$。
* **状态定义：** `dp[i][j]` 表示从起点走到坐标 `(i,j)` 有多少条路径。
* **转移方程：** 走到当前格子的路径总数 = 从上面掉下来的路径数 + 从左边走过来的路径数。
  `dp[i][j] = dp[i-1][j] + dp[i][j-1]`

## 45. 最长递增子序列 (Longest Increasing Subsequence)



**📝 题干描述：**

## 46. 最长公共子序列 (Longest Common Subsequence)

**📝 题干描述：**

**💡 核心思路 (二维基因图谱匹配)：**
* **极其巧妙的防越界 (Padding)：** 建立二维账本 `dp[n1+1][n2+1]`，在最上面和最左边垫一圈 `0`。这样在查阅 `i-1` 和 `j-1` 时绝对不会发生越界。
* **状态定义：** `dp[i][j]` 表示 `text1` 的前 `i` 个字符和 `text2` 的前 `j` 个字符的最长公共长度。
* **转移方程 (平行宇宙的互斥)：** * 基因匹配成功 (`text1[i-1] == text2[j-1]`)：白嫖左上角的历史记录，长度 `+1` 👉 `dp[i][j] = dp[i-1][j-1] + 1`
  * 基因匹配失败：绝不回头，分别查阅抛弃 `text1` 字符或抛弃 `text2` 字符的历史，取最大值 👉 `dp[i][j] = max(dp[i-1][j], dp[i][j-1])`
* **⚠️ 物理排雷：** 这两个状态是绝对互斥的，必须用 `if-else` 严格隔开！且账本是单调递增的，终局答案必定死死定格在右下角 `dp[n1][n2]`。

## 47. 编辑距离 (Edit Distance) - 💀 Hard

给你两个单词 `word1` 和 `word2`，请返回将 `word1` 转换成 `word2` 所使用的最少操作数（插入、删除、替换）。(LeetCode 72)

**💡 核心思路 (造物主的手术台)：**
* **状态定义：** `dp[i][j]` 表示把 `word1` 前 `i` 个字符改造成 `word2` 前 `j` 个字符的最少手术次数。
* **极其险恶的 Base Case (毁灭与无中生有)：** 把空串改成目标串，必须疯狂插入 (`dp[0][j] = j`)；把目标串改成空串，必须疯狂删除 (`dp[i][0] = i`)。绝不能初始化为 0！
* **转移方程 (三种手术的极限压榨)：**
  * 字符相同：免开尊口，直接继承左上角 👉 `dp[i][j] = dp[i-1][j-1]`

## 48. 下降路径最小和 (Minimum Falling Path Sum)

**💡 核心思路 (深渊坠落的逆向推演)：**
* **状态定义：** `dp[row][col]` 表示从第一行坠落到当前坐标 `(row, col)` 所承受的最小累计伤害。
* **Base Case：** 第一行的伤害就是它们本身的数字，直接平移赋值。
* **转移方程：** 站在当前格子，回头看头顶上三个可能掉下来的位置，选那个历史伤害最小的，加上自己这格的伤害。
* **⚠️ 致命 C++ 越界陷阱 (ASAN 段错误预防)：**

  * `col == 0` (最左边)：只能从正上、右上掉下来。
  * `col == n-1` (最右边)：只能从正上、左上掉下来。
  * 中间地带：三路皆可。

## 52. 目标和 (Target Sum)

**📝 题干描述：**
给定一个数组 `nums` 和一个目标数 `target`。向数组中的每个整数前添加 `+` 或 `-`。求有多少种符号组合能使总和等于 `target`。(LeetCode 494)

**💡 核心思路 (组合背包：方案数的狂欢)：**
* **初中代数降维打击：** 设正数集和为 $P$，负数集绝对值和为 $N$。
  $P - N = target$，且 $P + N = sum$。
  两式相加得出核心物理常量：$P = (target + sum) / 2$。
  问题瞬间坍缩为：**从数组中挑数字，有多少种方法能填满容量为 $P$ 的背包？**
* **N+1 终极防御矩阵 (二维 DP 的艺术)：**
  * 状态定义：`dp[i][j]` 表示用前 `i` 个数字，凑出容量 `j` 的方法总数。
  * **Base Case (万物起源)：** 开辟 `n+1` 行，第 0 行代表“没有数字的虚无状态”。`dp[0][0] = 1`（什么都不拿，也是一种方法），其余全为 0。
  * **转移方程 (路径累加)：** 装得下时：`dp[i][j] = dp[i-1][j] + dp[i-1][j-nums[i-1]]`
    装不下时：`dp[i][j] = dp[i-1][j]`

## 53. 跳跃游戏 (Jump Game)

**📝 题干描述：**
给定一个非负整数数组 `nums`，你最初位于第一个下标。数组中的每个元素代表你在该位置可以跳跃的最大长度。判断你是否能够到达最后一个下标。(LeetCode 55)

**💡 核心思路 (贪心降维 vs 动态规划)：**
* **DP 视角的痛点 ($O(N^2)$ 超时)：** DP 会建立一个 `bool dp[n]` 账本，对于每个格子 `i`，都要回头查阅前面所有的格子 `j`，看能不能跳过来（`dp[j] && j + nums[j] >= i`）。这导致大量重复的废操作。
* **贪心视角的降维打击 ($O(N)$ 绝杀)：**

  * 老板根本不关心具体怎么跳，只关心**“我的最远势力范围 (farthest) 能覆盖到哪”**。
  * **生死判定：** 如果当前格子 `i` 已经超出了 `farthest`，说明中间有断层（遇到了 0），直接宣告死亡 `return false`。
  * **贪婪扩张：** 只要能走到当前格子，就榨干它的价值，刷新最远边界：`farthest = max(farthest, i + nums[i])`。
  * **通关条件：** 只要 `farthest >= 终点坐标`，立刻通关！

## 54. 跳跃游戏 II (Jump Game II)

**📝 题干描述：**
与上一题类似，但题目保证你**一定**可以到达终点。求到达最后一个位置所需的**最少跳跃次数**。(LeetCode 45)

**💡 核心思路 (隐式 BFS 分层覆盖)：**
* **DP 视角的痛点 ($O(N^2)$)：** 记录每个格子的最少跳跃数 `dp[i] = min(dp[j] + 1, dp[i])`，同样需要极其昂贵的双层循环回溯。
* **贪心手电筒理论 ($O(N)$ 极致速通)：**
  * 我们不仅要记录探索到的最远边界 `farthest`，还要记录**当前这一跳能覆盖的极限距离 `current_end`**。
  * 这就像在黑夜里打手电筒：第一把手电筒照亮了区域 A。你在区域 A 里往前走，不用额外消耗手电筒，但你会一边走一边贪婪地往远处看，记住下一个最好跳板能照到的最远距离（更新 `farthest`）。
  * **结算时刻：** 当你走到区域 A 的绝对边缘（`i == current_end`），光线断了，你**被迫**必须按亮第二把手电筒！此时跳跃次数 `jumps++`，并且新的光照边界生效（`current_end = farthest`）。
  * **贪心的绝对正确性：** 在必须消耗 1 次跳跃的“势力范围”内，永远选择那个能把“下一步势力范围”推得最远的跳板，总跳跃次数在物理上必然最少。

## 61. 矩阵置零 (Set Matrix Zeroes)

**💡 核心思路 (物理空间管理 / 极致抠门的大堂记账法)：**
* **物理陷阱 (状态覆盖)：** 绝对不能见 0 就改，否则新改出来的 0 会引发“链式反应”，把原本无辜的数据全部污染。
* **大老板的抠门法则 (征用边界)：** 既然不允许开辟新数组，那就直接征用矩阵的**第 0 行和第 0 列**作为“临时账本”！

  2. **全城扫雷：** 遍历除边界外的矩阵。发现 `matrix[i][j] == 0`，就在它的十字准星尽头记账：`matrix[i][0] = 0` 且 `matrix[0][j] = 0`。

**💡 核心思路 (变治法 Transform / 状态机与环路探测)：**
* **物理转换：** 将“数字不断计算平方和”的过程，变治为“一个人在单向迷宫里不断走向下一个房间”。问题转化为：**如何探测这个人是否陷入了死循环？**

## 76. 霍纳法则极速求值 (Horner's Rule Evaluation)

**📝 题干描述：**
给定一个 $n$ 次多项式的系数数组 `coeffs` (按最高次幂到常数项排列)，以及一个给定的 $x$ 值。要求以低于 $O(N^2)$ 的时间复杂度计算多项式的结果。

**💡 核心思路 (变治法 / 化简实例 Instance Simplification)：**
* **物理陷阱：** 传统的代入计算会产生大量的重复乘法，一个 $n$ 次多项式需要做 $\frac{n(n+1)}{2}$ 次乘法，复杂度为极其臃肿的 $O(N^2)$。
* **霍纳魔法 (提取公因式)：** 将多项式 $a_n x^n + a_{n-1} x^{n-1} + \dots + a_0$ 变治为：
  $( \dots (a_n \cdot x + a_{n-1}) \cdot x + \dots ) \cdot x + a_0$
* **代码落地：** 只需维护一个结果变量 `res`，初始值为最高次系数 `coeffs[0]`。
  向后单层遍历数组，每次执行 `res = res * x + coeffs[i]`。

## 81. 存在重复元素 II (Contains Duplicate II)

**📝 题干描述：**

**💡 核心思路 (空间-时间权衡 / 哈希表记忆坐标)：**
* **物理陷阱：** 绝不能使用双层 `for` 循环向后探查，否则时间复杂度会退化为极其危险的 $O(N \cdot K)$，导致超时。同时遍历数组时必须严格遵守 `i < nums.size()`，绝不可加等号导致越界。
* **大厂级施工 (账本升级)：** 利用超级账本 `unordered_map<int, int>`。Key 记录数字，Value 记录该数字**最近一次出现的索引坐标**。
  1. 遍历数组，每次遇到数字，先在账本中查阅其“前世坐标”。
  2. 如果存在，且当前坐标 `i` 与账本记录坐标的差值 $\le k$，说明极其完美地命中了条件，立即开枪返回 `true`。

* **战术结算：** 利用哈希表将时间复杂度极限压榨至 $O(N)$，空间复杂度为 $O(N)$，极其经典的“空间换时间”打法。

## 82. 找出字符串中第一个匹配项的下标 (Implement strStr() - Horspool 算法)

**📝 题干描述：**
在主串 `haystack` 中找出模式串 `needle` 第一个匹配项的下标。如果不匹配，返回 `-1`。(LeetCode 28)

**💡 核心思路 (空间-时间权衡 / Boyer-Moore 精简版 - Horspool 算法)：**
* **物理陷阱：** 传统的双指针逐个字符向后探查，在遇到极度不匹配的字符串时，会退化为 $O(N \cdot M)$。比对时极其容易发生数组越界，必须严格区分主串的绝对坐标 `i` 和模式串的局部相对坐标。
* **第一阶段 (空间换时间建表)：**
  利用小写字母的特性，建立一个大小为 26 的 `shift` 表。
  1. 默认所有字符的跳跃距离为 `m`（模式串长度）。
  2. 遍历模式串的**前 $m-1$ 个字符**，更新其偏移量：`shift[needle[j] - 'a'] = m - 1 - j`。这代表了“坏字符”可以贪婪跳跃的安全距离。
* **第二阶段 (极其贪婪的尾部跳跃)：**
  将指针 `i` 对齐在主串中与模式串末尾重合的位置（初始为 $m-1$）。
  1. **从右往左**进行比对（偏移量为 $k$）：极其严谨地比较 `needle[m - 1 - k]` 和 `haystack[i - k]`。
  2. 如果完全匹配 ($k == m$)，直接返回起点坐标 `i - m + 1`。
  3. 如果匹配失败，直接读取主串中**对齐模式串尾部**的字符 `haystack[i]`，查表获取跳跃步数，执行极其暴躁的跨越：`i += shift[haystack[i] - 'a']`。
* **战术结算：** 利用一张极小的 26 容量的哈希表，以微小的空间开销，在最坏情况下虽然为 $O(N \cdot M)$，但在实际工业场景中极大概率能实现亚线性 $O(N/M)$ 的恐怖匹配速度。

## 86. 计算有向图的传递闭包 (Transitive Closure - Warshall 算法)

**📝 题干描述：**
给定一个 $N \times N$ 的有向图邻接矩阵，求其传递闭包。即在允许无限次中转的情况下，若节点 $i$ 能抵达节点 $j$，则结果矩阵 `dp[i][j] = 1`，否则为 `0`。

**💡 核心思路 (动态规划 / 逐步开放中转站)：**
* **数学与工程的物理映射：** 摒弃离散数学中晦涩的布尔矩阵连乘公式，将其还原为动态规划的“中转站开放”模型。
* **大厂级施工 (三重循环铁律)：**
  * **第一层循环（极其致命）：** 必须是中转站 $k$ 在最外层！这代表着动态规划的**阶段（Stage）**，即“我们当前开放了第 0 到 $k$ 个城市作为中转特权”。

  * **代数模拟版：** `dp[i][j] = max(dp[i][j], dp[i][k] * dp[k][j])`。利用乘法模拟必须同时联通的 AND 逻辑，利用 max 模拟保留连通性的 OR 逻辑。
  * **位运算极速版：** `dp[i][j] = dp[i][j] | (dp[i][k] & dp[k][j])`。底层硬件执行极快。
* **战术结算：** 时间复杂度 $O(N^3)$，空间复杂度 $O(N^2)$。代码极其凝练，是后续 Floyd 最短路径算法的绝对理论基石。

## 87. 最小覆盖子串 (Minimum Window Substring)

**📝 题干描述：**

**💡 核心思路 (动态滑动窗口 + 合规计数器策略)：**

## 88. 划分字母区间 (Partition Labels)
